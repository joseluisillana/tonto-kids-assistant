# TONTO Kids Assistant v1.0.0

Primera major del MVP conversacional: cierre del workflow Linux/Docker validado
y reducción de exposiciones accidentales de secretos. Sustituye como referencia
la etiqueta v0.6.1. No es el cierre de la fase final táctil/kiosk.

## Cambios desde v0.6.1

- Cliente táctil Kivy con cara animada y estados, assets y emulación Docker.
- Widgets Kivy reales probados bajo Xvfb/SDL2/Mesa en la CI.
- Host Linux + Docker + Bash; retirada de scripts PowerShell/Windows.
- Setup, cachés locales, limpieza Docker y emulador de audio estabilizados.
- Errores chat/STT y logs acotados, sin cuerpos upstream ni razones crudas.
- Setup/tests/build sin inyección de credenciales; montajes y build UI mínimos.
- Export NotebookLM con fuentes/destinos verificados y rechazo de enlaces.
- Versión del monorepo declarada en VERSION; metadatos web alineados a 1.0.0.

## Contrato y migración

Se mantienen GET /health, POST /chat y POST /chat/audio; WAV PCM mono 16 kHz,
16 bits y memoria corta en proceso. Backend Python/FastAPI, Raspberry thin
client con TTS local y web de validación. No cambia el contrato de éxito.

Los usuarios del antiguo workflow Windows/PowerShell deben usar Linux/Docker
con ./tonto.sh setup, dev, test, build y down según README y runbooks.
Se conserva .env para operación y el workflow SSH. No hay dependencias nuevas
ni cambios de versiones de dependencias en la preparación de esta release.

## Validación

La revalidación integrada posterior a #110 pasó setup, 175 pruebas Python,
25 Kivy, suite web y build; 22 casos de scripts auxiliares, seis turnos API
simulados, lifecycle/cleanup Docker, contexto UI y export/hook. Evidencia:
[spec de secretos](https://github.com/joseluisillana/tonto-kids-assistant/blob/v1.0.0/specs/agent-secrets-protection.md).
La preparación exige CI completa de la PR y de main antes de publicar.

La validación física anterior de migración está registrada por separado en
[matriz de migración](https://github.com/joseluisillana/tonto-kids-assistant/blob/v1.0.0/specs/migrate-linux-docker-validation.md).
La revalidación de #110 excluyó hardware/SSH reales, voz manual, proveedores
reales y activación systemd; no se atribuyen esas pruebas a esta revisión.

## Limitaciones y trabajo futuro

- #81/#88: kiosk y validación física final de la UI táctil pendientes.
- #114: demora del control de volumen del emulador aplazada.
- #53: proveedores futuros; DevExpert deprecado para operación real (D025).
- #110 cerrada en el alcance de exposiciones accidentales; aislamiento completo
  de secretos diferido, sin garantía frente a acceso deliberado del agente.
- mDNS requiere alternativa IP con identidad SSH verificada en esta LAN.
- TTS espeak básico, avisos de deprecación existentes y estado solo en memoria.
- Sin auth/cuentas/persistencia, wake word, modelos locales ni backend TTS.
