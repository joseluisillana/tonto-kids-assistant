# TONTO Kids Assistant v2.0.0

Versión mayor preparada por decisión explícita del operador en PR #126.
Estas notas están listas para publicación tras merge y CI; no acreditan un
tag ni una GitHub Release publicados. VERSION y metadatos web declaran 2.0.0.

## Cambios desde v1.0.0

- Instrucciones portables para agentes reorganizadas por componentes y registros
  de specs/issues locales migrados a ai/, con planes y journals propios.
- Arranque oficial del emulador Kivy en Docker Desktop Linux, con detección
  del daemon y puentes temporales de pantalla X11 y audio ligados a loopback.
- Plugin ALSA–PulseAudio dentro de la imagen, configuración activa en Desktop
  y renderizado por software. Se conserva la vía existente de Engine nativo.
- Preflight de recursos/puertos y limpieza de contenedor, puentes y override
  al cerrar, fallar o interrumpir el launcher.
- Fallos de captura muestran error directamente; selección inválida de entrada
  y duración de grabación se manejan sin dejar la UI atascada.
- Guía humana e instrucciones de agentes con contexto explícito y cierre de
  ventana anterior antes de repetir el arranque.

## Compatibilidad y operación

El salto mayor responde a la decisión de versión del operador; no introduce
rupturas del contrato GET /health, POST /chat o POST /chat/audio. Se mantiene
WAV PCM_16 mono a 16 kHz y conversación en memoria. Raspberry y proveedores
conservan sus contratos. No cambian versiones/rangos de dependencias web.

Desktop requiere sesión X11 local, autorización previa del usuario, socat y
setsid existentes en el host y PipeWire/PulseAudio para voz. No se instalan
paquetes host automáticamente ni se desactiva el control X11. Los puentes
confían en procesos locales y no escuchan en LAN. Preparar dependencias en
el mismo contexto con `DOCKER_CONTEXT=desktop-linux ./tonto.sh setup`.

Desde raíz, cerrar ventana anterior y esperar limpieza antes de repetir:

```bash
DOCKER_CONTEXT=desktop-linux ./tonto.sh dev ui
```

## Validación

Issue local [003](../../ai/issues/003-kivy-docker-development-audio/issue.md) y
su [journal](../../ai/issues/003-kivy-docker-development-audio/journal.md): setup,
188 pruebas Python, 29 Kivy, aceptación humana de voz/texto, recreación y limpieza
con backend y UI en Desktop. Tests web/build de la preparación de versión se
registran en ese journal; CI del commit integrado es gate de publicación.

Dos turnos fallaron por red en STT de OpenAI y los posteriores funcionaron.
No se acredita su causa exacta ni disponibilidad continua de red/proveedor.
La aceptación Desktop no sustituye validación final de hardware Raspberry.
